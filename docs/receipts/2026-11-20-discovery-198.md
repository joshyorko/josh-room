## Scope and limits

This is an incremental, read-only discovery vertical, not full #198 completion.
The new `composition inventory` JSON-lines session and native picker enumerate
all accessible supported directories, including policy-excluded paths and deep
ordinary directories inside cohesive repositories. SQLite holds metadata on disk;
entry work, sibling finalization, validation, UI pages and transport are bounded
per batch. Linux mount-aware, descriptor-relative no-follow traversal fails closed.
Root Room markers are compatible; nested markers and Git pointers stop branches.
The root Git recommendation stays workspace-level. Suggested boundaries have
explicit evidence/reasons; all safe manual choices remain available.

Pause/resume is **live-process only**. Process loss requires restarting the scan;
crash cleanup and durable cross-process resumption remain incomplete. A completed
observation is not a snapshot or lock: changes detected at scan validation or
manual ancestor validation mark choices stale. Regular-file payload changes are
not tracked. No claim of complete file inventory, Git validation, Save readiness,
JAT hydration, retention or data isolation follows from discovery.

Dataset-specific size ranking and durable resume remain PR D acceptance gaps.
The legacy `composition plan` API retains its old bounded behavior for existing
clients; the native picker no longer uses it. No v1 schema limits are raised.
Scalable composition storage and tri-state assignment remain PR E; publication
and hydration remain PR F. Ordinary New Room/Save semantics are unchanged.
