# PCC Crypto #10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stream validated #9 session evidence through managed age into randomized ciphertext-only prepared state owned by the existing #8 outbox.

**Architecture:** `pcc_crypto.py` validates actual `NormalizationEvent` documents, resolves an immutable recipient set from a host-owned #3 profile seam, writes a manifest-plus-one-payload envelope through age pipes, and hashes the ciphertext into an adjacent temporary file. An additive file-backed #8 handoff moves that fsynced ciphertext into a durable prepared binary object and publishes only validated delivery metadata. Source, VS Code runtime, and room-template controller copies remain byte-identical.

**Tech Stack:** Python 3.12, existing managed `age`/`age-keygen` executables, `subprocess.Popen`, streaming `tarfile` envelope framing, SHA-256, `pytest`, `ruff`, existing JSON/schema/policy/outbox contracts.

**Spec:** `docs/superpowers/specs/2026-09-22-pcc-crypto-10-design.md`

## Global Constraints

- The encryption boundary consumes the actual #9 `NormalizationEvent` shape and validates every v1 evidence document.
- The managed age executable is launched with public recipients only; private identities never enter argv, environment, logs, receipts, or metadata.
- No complete plaintext or ciphertext is materialized in memory; no durable plaintext staging is created.
- Every immutable object is independently randomized and encrypted; ciphertext SHA-256 is the only public object identity.
- Production/private-R2 profiles require distinct daily-use and independent recovery recipients resolved from the #3 host-owned recipient-set reference.
- Unknown major/schema, wrong kind, reference mismatch, digest/size mismatch, recipient errors, age failures, and publication failures fail closed.
- The existing byte-based `PccOutbox.prepare_encrypted` compatibility API remains unchanged; the new handoff is additive and file-backed.
- No hooks, R2, MinIO, device enrollment, sender attestation, deterministic encryption, or historical re-encryption is in scope.

## Review Focus

- Asset events have only the #9 `asset_receipt`; the production API must require an ephemeral caller-owned payload stream and never invent a path or buffer the asset.
- A crash after ciphertext rename but before queue-state publication must be recoverable without duplicate publication or plaintext residue.
- Public prepared JSON must not contain event documents, plaintext digests, private paths, recipients, or transcript text even though encrypted manifest content contains the required bindings.
- Recipient validation must not silently reduce a production set to one recipient or accept an event-selected profile/reference.
- A valid age ciphertext with a modified encrypted manifest or truncated payload must be rejected after decryption, not treated as a prepared object.
