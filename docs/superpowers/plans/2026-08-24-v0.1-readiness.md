# Josh Room v0.1 Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver bounded-memory snapshot operations, explicit host setup, an immutable release tuple, secure-image evidence, and enforced public CI for the existing Josh Room product.

**Architecture:** Preserve all current formats and service boundaries while adding file-oriented crypto, envelope, and local-store primitives. Switch snapshot operations to those primitives, then pin and prove the existing runtime tuple without adding new product behavior.

**Tech Stack:** Python 3.12+, age CLI, tarfile, JAT/RCC, Cloudflare R2 S3 API, Dev Containers/DevPod, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-24-v0.1-readiness-design.md`

## Global Constraints

- Preserve envelope format version 1 and JAT Hauler payload bytes.
- Preserve catalog, object-key, request/result, and snapshot behavior.
- Snapshot-sized data never enters a Python `bytes` object.
- Peak transfer chunks are at most 1 MiB unless an existing SDK requires a smaller buffer.
- Catalogs remain bounded bytes metadata.
- Host setup owns persistent writes; Room config remains read-only.
- Do not add RCC Environment Artifacts, Actions, Hive orchestration, extensions, daemons, or providers.
- Do not tag or release v0.1 in this plan.
